# 경량 자산 포맷 `.skla` v1.0 명세

skylens-renderer 경로 B(자산 경량화)의 조각 파일 포맷이다. 2단계(경로 A) 서버 렌더러도 이 포맷을 그대로 입력으로 쓴다.
코드 계약은 `contracts/asset/index.mjs`(상수·타입·`parseHeader`·`serializeHeader`·`bodyLayout`)와 `contracts/asset/stubs.mjs`(하위 작업 인터페이스)이고, 골든 파일은 `fixtures/asset_golden/` 에 있다.
이 문서와 코드의 수치가 다르면 이 문서가 이긴다. 문서를 고칠 때는 코드·골든·사이드카를 같은 커밋에서 맞춘다.

## 0. 한눈에

| 항목 | 값 |
|---|---|
| 확장자·매직 | `.skla`, 파일 앞 4바이트 `53 4B 4C 41`(ASCII `SKLA`) |
| 버전 | 주 1, 부 0 |
| 바이트 순서 | 모든 다바이트 값 little-endian |
| 파일 1개 | 조각(chunk) 1개 = 헤더 128 B(+확장) + 본문 |
| 입력 형식 | 27 B 점(형식 1)과 56 B 가우시안(형식 2), 한 포맷에 공통 필드 + 형식별 선택 필드 |
| 본문 배치 | 필드별 평면 배열(SoA), 평면마다 4바이트 정렬 |
| 좌표 | GeoAnchor 기준 로컬 ENU, 1 unit = 1 m |
| 타일 | ENU 사각 격자 한 변 64 m |
| 위치 양자화 | 축마다 u16, 단계 2^-quant_exp m (quant_exp 8..10) |
| 점당 본문 바이트 | 형식 1: 11 B (원본 27 B 의 40.7%), 형식 2: 17 B (원본 56 B 의 30%) |
| 체크섬 | CRC-32(IEEE), 체크섬 필드를 0 으로 본 파일 전체 |

## 1. 좌표계와 타일

### 1.1 좌표
- 모든 위치는 **GeoAnchor 기준 로컬 ENU, 1 unit = 1 m** 이다(RULES §1.3). 축 순서는 `[e, n, u]` = (동, 북, 위).
- 원본 PLY 의 `x y z` 는 ENU 의 (e, n, u) 로 읽는다(가정, T04 확인 전)(renderer_basis §1-3 의 "동-북-위" 표기). PLY → ENU 변환과 GPS ↔ ENU 는 T04 가 skylens `geo.ts` 와 같은 식으로 한다. 씬 좌표(x=동, y=위, z=−북)로의 변환은 그리는 쪽에서 하고 **포맷에 저장하지 않는다.**
- 화면 좌표·임의 정규화 좌표는 저장하지 않는다. 양자화 원점(`bbox_min`)과 타일 원점은 ENU 값이다.
- 렌더러는 이 좌표를 세계 좌표 X_w 로 보고 renderer_basis §2-1 의 `X_c = R·X_w + t`, `[u,v,1]ᵀ ∝ K·X_c` 로 투영한다. 포맷은 카메라 값을 담지 않는다.
- 헤더의 `anchor_lat/lon/alt` 는 이 조각의 ENU 원점인 GeoAnchor 다. 같은 장면의 조각은 모두 같은 앵커를 가져야 하고, 다르면 읽는 쪽이 거부한다(섞어 그리지 않는다).

### 1.2 타일 색인
- 한 변 `TILE_SIZE_M = 64` m 의 ENU 사각 격자, 원점 = GeoAnchor(e = 0, n = 0).
- `tile_x = floor(e / 64)`, `tile_y = floor(n / 64)`. 구간은 반열린 `[64·tile_x, 64·tile_x + 64)` 이다. 예: e = 64.0 → tile_x = 1, e = −0.001 → tile_x = −1.
- u(높이)는 타일을 가르지 않는다. 한 조각의 u 범위는 §5.1 양자화 범위 안이어야 하고, 넘으면 쓰는 쪽이 u 방향으로 조각을 나눈다(같은 타일, 다른 chunk_index).
- 한 조각의 모든 점은 한 타일 안에 있다: `64·tile_x ≤ bbox_min.e`, `bbox_max.e < 64·tile_x + 64`, n 도 같다.
- 타일 전체 폭(≥ 63.999 m)을 쓰는 조각은 quant_exp ≤ 9 를 쓴다(§5.1).
- 64 m 를 고른 이유: §5.1 의 가장 고운 단계(2^-10 m)에서 u16 이 덮는 길이가 65535 × 2^-10 = 63.999 m 라 타일 한 변과 맞는다. 구간 하나의 비행 범위(수십~수백 m, 추정)를 수~수십 타일로 나눠 컬링 단위로 쓰기에 적당하다(추정, T07·T08 에서 측정).

## 2. 파일 구조

```
[헤더 header_size 바이트] [본문 body_bytes 바이트]
 ├ 기본 헤더 128 B          ├ 필수 평면(형식별, §4)
 └ 헤더 확장 영역(부 버전↑)  └ 확장 평면 영역(부 버전↑, §9)
```
- 파일 길이 = `header_size + body_bytes` 이어야 한다. 뒤에 남는 바이트가 있으면 거부한다.
- 파일 하나 = 조각 하나다. 조각은 (구간, 수준, 타일, LOD, 조각 번호) 로 식별한다(§11).

## 3. 헤더

### 3.1 배치 (기본 128 B)

| 오프셋 | 크기 | 형 | 이름 | 뜻 |
|---:|---:|---|---|---|
| 0 | 4 | u8×4 | magic | `53 4B 4C 41` ('SKLA') |
| 4 | 2 | u16 | version_major | 1 |
| 6 | 2 | u16 | version_minor | 0 |
| 8 | 2 | u16 | header_size | 128 이상, 4의 배수. 128 을 넘는 부분 = 헤더 확장 영역 |
| 10 | 1 | u8 | format | 1 = 27 B 점, 2 = 56 B 가우시안 |
| 11 | 1 | u8 | codec | 0 = 무압축 평면(§4). 다른 값은 T09 가 정한다 |
| 12 | 4 | u32 | seg_level | `segment_id·4 + level` (§11) |
| 16 | 4 | u32 | point_count | 점 수, 1 이상 |
| 20 | 4 | i32 | tile_x | §1.2 |
| 24 | 4 | i32 | tile_y | §1.2 |
| 28 | 2 | u16 | tile_size_m | 64 (v1 고정. 자기 기술용, 다르면 거부) |
| 30 | 1 | u8 | lod | LOD 단계 0..7, 0 = 가장 세밀 (§10) |
| 31 | 1 | u8 | quant_exp | 위치 양자화 단계 = 2^-quant_exp m, 8..10 |

| 36 | 4 | u32 | body_bytes | 본문 바이트(필수 평면 + 확장 평면) |
| 40 | 24 | f64×3 | bbox_min | 조각 점들의 축별 최솟값 [e, n, u] = 양자화 원점 |
| 64 | 24 | f64×3 | bbox_max | 조각 점들의 축별 최댓값 [e, n, u] |
| 88 | 8 | f64 | anchor_lat | GeoAnchor 위도(도) |
| 96 | 8 | f64 | anchor_lon | GeoAnchor 경도(도) |
| 104 | 8 | f64 | anchor_alt | GeoAnchor 고도(m) |
| 112 | 4 | u32 | checksum | §7 |
| 116 | 12 | u8×12 | reserved | v1.0 은 0 으로 쓴다 |

f64 필드는 모두 8바이트 정렬 위치에 있다. 헤더 128 B 는 점 수십 개 조각에서는 무겁지만 조각 하나가 보통 수천 점 이상이라 1% 안팎이다(추정).

### 3.2 필드 규칙 (엄격 읽기·검증기가 검사)
1. magic 일치, version_major = 1 (§9).
2. header_size ≥ 128, 4의 배수, 파일 길이 이하.
3. format ∈ {1, 2}, codec 은 읽는 쪽이 아는 값(v1.0 은 0 만).
4. level = seg_level & 3 은 자동으로 0..3, segment_id = seg_level >>> 2 는 0..2^30−1.
5. point_count ≥ 1. 점이 없는 조각은 만들지 않는다("없음"은 전송 규약이 알린다, T11).
6. tile_size_m = 64, lod ≤ 7, quant_exp ∈ {8, 9, 10}.
7. bbox_min·bbox_max 유한, 축마다 min ≤ max, (max − min)·2^quant_exp ≤ 65535.
8. bbox 의 e·n 범위가 (tile_x, tile_y) 타일 안(§1.2).
9. anchor 세 값 유한.
10. body_bytes ≥ 필수 평면 합(§4), header_size + body_bytes = 파일 길이.
11. version_minor = 0 이면 reserved 12바이트가 모두 0. version_minor > 0 이면 reserved 를 검사하지 않는다(상위 부 버전이 쓸 수 있다).
12. checksum 일치(§7).

`parseHeader`(계약)는 1·2·3 의 format 만 본다(최소 검사). 나머지는 T03.1 `readHeaderStrict` 와 T03.6 `validateAsset` 이 한다.

## 4. 본문 배치 — 필드별 평면 배열(SoA)

### 4.1 결정과 근거
본문은 **필드(성분)마다 하나의 연속 배열(평면)** 로 둔다. 점마다 필드를 붙여 두는 구조체 배열(AoS)은 쓰지 않는다.

| 근거 | 내용 |
|---|---|
| 압축률(측정) | 합성 지면 20만 점(64 m 타일, 모턴 순서, 점당 11 B: u16 위치·u8 색·snorm8 법선)을 deflate(level 9)로 눌렀다. AoS 2,057,625 B, SoA 1,803,448 B(AoS 의 0.876), SoA + u16 평면 바이트 분리 1,433,299 B(0.697). 같은 성질의 값이 붙어 있어 엔트로피 부호화(T09)가 유리하다. 합성 데이터 측정이고 실자산 측정은 T09.7 이 한다 |
| 선택 필드 | 형식별 선택 필드(법선 / 불투명도·크기·회전)가 "평면이 있다·없다"로 표현된다. 공통 평면(위치·색)의 배치는 두 형식이 같다 |
| GPU 업로드 | WebGL2 `vertexAttribPointer` 는 속성마다 다른 버퍼를 받는다. u16 위치는 정규화 정수 속성으로 바로 올린다(복사 없음, 4바이트 정렬) |
| 호환 | 부 버전이 평면을 더할 때 필수 평면 뒤에 붙이면 옛 읽기는 건너뛰면 된다(§9) |
| 대가 | 조각 안에서 앞부분만 받아 그리는 점진 표시가 안 된다(평면 하나를 다 받아야 다음 평면). 점진은 조각·LOD 단위로 한다(T07.9). 점 하나를 읽으려면 평면 수만큼 떨어진 곳을 읽는다 |

codec 0 은 평면을 그대로 둔다(바이트 분리·차분·엔트로피 부호화 없음). 측정에서 이득이 큰 바이트 분리·차분은 T09 가 codec 값으로 더한다.

### 4.2 평면 순서와 크기
평면은 아래 순서로 놓는다. 평면 i 의 크기 = point_count × 원소 크기, 다음 평면은 4의 배수 위치에서 시작하고 사이 채움 바이트는 0 이다.
`pad4(x) = x + (4 − x mod 4) mod 4`.

**공통 평면(두 형식)**

| 순서 | 이름 | 형 | 내용 |
|---:|---|---|---|
| 1 | pos_e | u16 | 위치 e 양자화 값 (§5.1) |
| 2 | pos_n | u16 | 위치 n |
| 3 | pos_u | u16 | 위치 u |
| 4 | color_r | u8 | 색 r (§5.2) |
| 5 | color_g | u8 | 색 g |
| 6 | color_b | u8 | 색 b |

**형식 1(27 B 점) 선택 평면**

| 순서 | 이름 | 형 | 내용 |
|---:|---|---|---|
| 7 | normal_oct_x | i8 | 법선 팔면체 사상 x, −127..127 (§5.3) |
| 8 | normal_oct_y | i8 | 법선 팔면체 사상 y |

**형식 2(56 B 가우시안) 선택 평면**

| 순서 | 이름 | 형 | 내용 |
|---:|---|---|---|
| 7 | opacity | u8 | 시그모이드 뒤 불투명도 (§5.5) |
| 8 | scale_0 | u8 | ln 크기 (§5.6) |
| 9 | scale_1 | u8 | |
| 10 | scale_2 | u8 | |
| 11 | rotation | u32 | 회전 smallest-three (§5.4) |

필수 본문 바이트(n = point_count):
- 형식 1: `3·pad4(2n) + 5·pad4(n)` — n 이 4의 배수면 11n.
- 형식 2: `3·pad4(2n) + 7·pad4(n) + 4n` — n 이 4의 배수면 17n.

골든 확인: 형식 1, n = 32 → 3·64 + 5·32 = 352. 형식 2, n = 21 → 3·44 + 7·24 + 84 = 384.

## 5. 부호화 식 (원본 → 저장 값)

### 5.0 공통
- 반올림 `round(x) = floor(x + 0.5)` (0.5 는 올림). 모든 언어 구현이 이 정의를 쓴다.
- `clamp(x, lo, hi)`.
- 계산은 f64 로 한다. 입력 f32 값은 f64 로 올려 그대로 쓴다.

### 5.1 위치
- `bbox_min`, `bbox_max` = 조각 점들의 축별 최소·최대(f64, 원본 f32 값이라 정확히 담긴다).
- `quant_exp` = 10, 9, 8 순서로 모든 축에서 `(max − min)·2^k ≤ 65535` 인 가장 큰 k. 셋 다 안 되면(어느 축이든 범위 > 65535 × 2^-8 = 255.996 m) 조각을 나눈다.
- `q = clamp(round((x − min)·2^quant_exp), 0, 65535)`.
- 덮는 길이: quant_exp 10 → 63.999 m, 9 → 127.998 m, 8 → 255.996 m.

### 5.2 색
- 형식 1: 원본 `r g b` u8 를 그대로 둔다(손실 없음).
- 형식 2: `c_k = clamp(round((0.5 + C0·f_dc_k)·255), 0, 255)`, `C0 = 0.28209479177387814`(구면 조화 0차). 고차 구면 조화 계수(`f_rest_*`)는 v1 에 담지 않는다(§14).

### 5.3 법선 (형식 1) — 팔면체 사상 snorm8
```
l1 = |x| + |y| + |z|;  u = x / l1;  v = y / l1
z < 0 이면 (u, v) ← ((1 − |v|)·sgn(u), (1 − |u|)·sgn(v))     sgn(0) = +1
qx = clamp(round(u·127), −127, 127);  qy = clamp(round(v·127), −127, 127)
```
법선은 위치와 같은 ENU 축 세계 좌표다(단위 길이 미보장). 원본 부호를 보존하고, 축 변환 시 같은 회전을 적용한다.
길이 0·NaN 법선은 쓰는 쪽이 거부한다(T04.8 에서 걸러진 입력만 받는다). 빈 법선을 임의 방향으로 채우지 않는다.

### 5.4 회전 (형식 2) — smallest-three 10비트
PLY `rot_0..3` = (w, x, y, z).
```
q ← q / |q|
m = |q_k| 가 가장 큰 k (같으면 작은 k)
q_m < 0 이면 q ← −q            (q 와 −q 는 같은 회전)
나머지 세 성분(k ≠ m, k 오름차순) a_j = clamp(round(q_k·√2·511) + 511, 0, 1022)
packed = (m << 30) | (a_0 << 20) | (a_1 << 10) | a_2      (u32)
```
나머지 성분은 |q_k| ≤ 1/√2 라 a ∈ 0..1022 에 들어간다. 1023 은 쓰지 않는다(검증기가 거부).

### 5.5 불투명도 (형식 2)
PLY `opacity` 는 로짓(시그모이드 이전) 값이다. `α = 1 / (1 + e^(−opacity))`, `q = clamp(round(α·255), 0, 255)`.

### 5.6 크기 (형식 2)
PLY `scale_k` 는 ln s 다. `q = clamp(round((scale_k + 10)·16), 0, 255)`. 표현 범위 ln s ∈ [−10, 5.9375] (s ≈ 4.5e−5 m ~ 379 m), 단계 1/16.

## 6. 복원식 (저장 값 → 원본 형식, T03.7)

| 필드 | 복원 |
|---|---|
| 위치 | `x = bbox_min + q·2^-quant_exp` (f64), 원본 레코드에는 f32 로 내린다 |
| 색(형식 1) | 그대로 |
| 색(형식 2) | `f_dc_k = (c_k / 255 − 0.5) / C0` |
| 법선 | `u = qx/127, v = qy/127, z = 1 − |u| − |v|`; z < 0 이면 (u, v) ← ((1 − |v|)·sgn(u), (1 − |u|)·sgn(v)); (u, v, z) 정규화 |
| 회전 | 나머지 세 성분 `q_k = (a − 511) / (511·√2)`, `q_m = √max(0, 1 − Σq_k²)`, 전체 정규화. 출력 (w, x, y, z) |
| 불투명도 | `α = clamp(q / 255, 1/510, 509/510)`, `opacity = ln(α / (1 − α))` (q = 0·255 에서 ±∞ 를 막는다) |
| 크기 | `scale_k = q / 16 − 10` |

원본 레코드: 형식 1 은 `x y z nx ny nz` f32 + `r g b` u8 = 27 B, 형식 2 는 `x y z f_dc_0..2 opacity scale_0..2 rot_0..3` f32 = 56 B, little-endian, 점 순서 = 본문 순서.

## 7. 체크섬
- 알고리즘: CRC-32 (IEEE 802.3, 반사 다항식 0xEDB88320, 초기값 0xFFFFFFFF, 끝 XOR 0xFFFFFFFF). zlib `crc32` 과 같다. 시험값: `"123456789"` → 0xCBF43926, `"abc"` → 0x352441C2.
- 범위: 파일 바이트 `[0, header_size + body_bytes)` 전체. 단 오프셋 112..115(checksum 필드)는 0 으로 보고 계산한다. 헤더 확장 영역과 본문 확장 평면도 포함한다.
- 성질: 1비트 뒤집기는 전부 검출한다(CRC-32 의 성질, T03.5 `checksum_detects_flip` 이 확인). 변조 방지용이 아니다.

## 8. 역변환 오차 상한

원본 값과 §6 복원 값의 차이 상한. T03.7 `unpack_error_bound` 가 두 형식 모두 이 표로 검사한다.

| 필드 | 상한 | 비고 |
|---|---|---|
| 위치(축마다, f64 복원) | 2^-(quant_exp+1) m: qexp 10 → **0.48828125 mm**, 9 → **0.9765625 mm**, 8 → **1.953125 mm** | 반 단계 |
| 위치(축마다, f32 원본 레코드) | 위 값 + f32 반올림. \|좌표\| < 4096 m 에서 + 2^-13 m = 0.1220703125 mm → qexp 10 이면 **0.6103515625 mm** | \|좌표\| ≥ 4096 m 면 f32 반 ulp 만큼 더 커진다 |
| 색(형식 1) | **0** | 손실 없음 |
| f_dc(형식 2) | **0.5 / (255·C0) = 0.0069507** | 0.5 + C0·f_dc ∈ [0, 1] 인 원본만. 밖은 잘림(오차 = 범위까지 거리 + 위 값) |
| 법선 각 | **1.0°** | 측정 최대 0.954°(무작위 400만 방향), 0.952°(팔면체 격자 2,500만 점) |
| 불투명도 α | **1/510 = 0.0019608** | 시그모이드 뒤 α 기준. 로짓 값 자체의 상한은 두지 않는다(α → 0·1 에서 발산) |
| 크기 ln s | **1/32 = 0.03125** (s 상대 오차 ≤ 3.2%) | ln s ∈ [−10, 5.9375] 인 원본만. 밖은 잘림 |
| 회전 각 | **0.3°** | 해석 상한 약 0.275°(성분 반 단계 1/(2·511·√2) 에서 복원 성분 오차 포함), 측정 최대 0.2498°(무작위 400만) |

f_dc·불투명도·크기 상한은 f64 복원 기준이다. f32 로 내리면 반올림 몇 ulp(f_dc 기준 약 1e-7)가 더해질 수 있고, 저장 구간 경계에 정확히 걸린 원본(로짓 0, f_dc 0)은 구현이 반올림 방향을 아래로 골라 상한 안에 둔다(T03.7). 회전은 반올림 뒤에도 가장 큰 성분이 0 이상이 되도록 부호 전체를 뒤집을 수 있다(같은 회전).

위치 상한은 renderer_basis §3-7(§11 Q 참조) 의 깊이 해상도와 비교해 작다: 깊이 45.3 m·기선 8.26 m 에서 1 px 시차 = 0.33 m(고도 30 m, 60° 사선), 부화소 정합(0.1~0.2 px)이면 수 cm 이므로 1 mm 이하 양자화는 원본 정밀도를 해치지 않는다.

## 9. 버전 호환 정책

| 경우 | 동작 |
|---|---|
| version_major ≠ 1 (0 = 구버전, 2 이상 = 미래) | **거부** (`AssetFormatError` code `version`) |
| version_major = 1, version_minor ≤ 읽는 쪽 부 버전 | 받아들인다 |
| version_major = 1, version_minor > 읽는 쪽 부 버전 | 받아들이고 **모르는 영역을 무시**한다: 헤더 확장 영역 `[128, header_size)`, reserved 12 B, 본문의 필수 평면 뒤 `[필수 합, body_bytes)` |
| codec 을 모름 | 부 버전과 무관하게 거부 (code `codec`) |
| format 을 모름 | 거부 (code `format`) |

부 버전을 올려도 되는 변경: 헤더 확장 영역에 필드 추가, reserved 사용, 필수 평면 뒤에 확장 평면 추가, 새 codec 값 추가(옛 읽기는 그 codec 파일을 거부한다).
주 버전을 올려야 하는 변경: 기본 헤더 128 B 의 기존 필드 의미·위치 변경, 필수 평면 순서·형 변경, 부호화 식(§5) 변경, 오차 상한(§8)을 키우는 변경.
쓰는 쪽은 언제나 현재 버전(1.0)으로 쓴다.

## 10. LOD 와 딜레이 패턴 수준

### 10.1 LOD
- `lod` 0..7. 0 = 그 (구간, 수준, 타일)에 도착한 점 전부. 숫자가 클수록 성기다.
- 단계 간격의 근거는 renderer_basis §3-7 의 깊이 해상도 `Δd ≈ d_c²/(f·b)` 다. 여기서 d_c 는 촬영 깊이, Δd 는 의미 있는 점 간격의 하한(=밀도 상한)이며 깊이 방향 값이다. Δd(촬영 깊이 d_c 기준)는 lod 0 의 깊이 방향 정밀도 한계로만 쓰고(renderer_basis §11 Q), 시점 거리별 간격은 화면 픽셀 크기로 정한다(SPEC §2 표, 렌더러 결정). 단계별 거리표·밀도 규칙은 T07 계약(`contracts/lod/`)이 정하고, 이 포맷은 번호만 싣는다. 두 입력 형식에 같은 규칙을 쓴다(결정 0012).
- LOD 는 도착한 점을 **줄이는** 쪽으로만 쓴다(RULES §1.2). lod k 조각의 위치는 같은 (구간, 수준, 타일) 에 도착한 점 위치의 부분집합이다(양자화 오차 §8 안). 새 점을 만들지 않는다. 색·법선 등의 대표값은 T07.6·T07.7 규칙을 따른다.
- 같은 (구간, 수준, 타일) 의 LOD 들은 **서로 바꿔 끼우는 표현**이다. 그리는 쪽은 한 시점에 (구간, 수준, 타일) 마다 LOD 하나만 그린다. 서로 다른 LOD 를 겹쳐 그리지 않는다.
- 같은 (구간, 수준, 타일, LOD) 의 서로 다른 chunk_index 는 점을 나눈 것(서로소)이라 함께 그린다.

### 10.2 딜레이 패턴 수준(교체, 누적 아님)
- `level` 0..3 = 학습 스텝 250 / 1,000 / 3,500 / 7,000 (RULES §1.1).
- 구간 S 의 수준 L 조각이 도착하면, 그리는 쪽(서버·클라이언트 모두)은:
  1. S 에 이미 L 보다 높은 수준이 있으면 이 조각을 **버린다**(추월당한 수준 건너뛰기).
  2. S 에 L 보다 낮은 수준의 조각이 있으면 그 조각들을 **모두 버리고** 이 조각으로 바꾼다(누적·겹쳐 그리기 금지).
  3. 같은 수준이면 더한다(같은 수준의 다른 타일·LOD·조각).
  4. 같은 키(§11) 조각은 교체(중복 더하기 금지).
- 판정에는 헤더의 (segment_id, level) 만 쓴다. 수준 진행은 skylens 코어의 도착 이벤트만 정하고, 렌더러는 타이머로 수준을 올리지 않는다. 앵커가 다른 조각은 상태 기계(T10)가 거부한다. 파서는 조각 단독이라 앵커를 검사하지 않는다.
- 도착하지 않은 (구간, 수준, 타일) 은 "없음"으로 표시한다. 다른 수준·LOD·이웃 타일로 메우지 않는다.
- 상태 기계 구현은 T10 이 한다. 이 포맷은 판정에 필요한 식별자를 모든 조각 헤더에 싣는 것까지 책임진다.

## 11. 식별자
- `seg_level = segment_id·4 + level` (u32). segment_id ∈ [0, 2^30), level ∈ [0, 3]. 복원: `segment_id = seg_level >>> 2`, `level = seg_level & 3`.
- 조각 키 = (segment_id, level, tile_x, tile_y, lod, chunk_index). 정규 문자열: `${segment_id}.${level}.${tile_x}.${tile_y}.${lod}.${chunk_index}` (10진, 음수 타일만 '-' 부호, 앞자리 0 없음). 예: 골든 point27 → `7.2.1.-2.0.0`, gauss56 → `7.3.0.0.1.2`.

## 12. 결정성
- 같은 입력(같은 점 순서·같은 값·같은 식별자·같은 앵커) → 같은 바이트. 채움·reserved 는 0, 반올림은 §5.0, 체크섬은 마지막에 채운다.
- 점 순서는 쓰는 쪽이 정한다. 재배치(공간 채움 곡선, T09.4)를 하면 그 순서도 결정적이어야 한다.
- f64 계산은 IEEE 754 결정적이다. `Math.exp`(불투명도) 는 엔진마다 마지막 비트가 다를 수 있으나 round 경계(…0.5)에 걸리지 않는 한 결과가 같다. 경계에 걸리는 입력은 측정되지 않았다(열린 문제).

## 16. 열린 문제
- 쓰기(packer) 하위 작업이 TASKS T03 표에 없다. `packChunk` 소유를 작업자가 정한다(T03.9 결정성 시험도 packer 가 있어야 돌 수 있다).
- 원본 PLY x y z 가 ENU (e, n, u) 라는 가정은 renderer_basis 표기에서 나왔다. 실제 skylens 자산 축은 T04 가 확인한다.
- 불투명도 `Math.exp` 의 엔진 간 마지막 비트 차이가 round 경계에서 바이트를 바꿀 수 있는지 미측정.
- 법선 상한 1.0° 는 측정 최대 0.954° 와 여유가 작다. T09.2 기준(1°)과 같아 그대로 두었다.
